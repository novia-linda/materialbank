## ORDER MODEL – IMPORTANT

Keep the data model intentionally simple for this teaching prototype:

ONE COURSE SEAT = ONE ROW IN GOOGLE SHEETS.

Each saved row must contain only one ProductID and one ProductName.

Do not store multiple courses in one cell using separators such as | or commas.

Examples:

If a customer buys:
P001 x 1
P003 x 1

create TWO rows.

If a customer buys:
P001 x 2

create TWO P001 rows.

Customer information may therefore appear on several consecutive rows. This is intentional.

Each row must have its own unique OrderID.

OrderNote
- from checkout Order note
- may be blank

Status

New

LastUpdated
- initially set to the same time as CreatedAt

## CHECKOUT FLOW

Keep the existing Day 1 checkout UI and validation.

When the user clicks Send order / Skicka beställning:

1. validate the existing checkout fields
2. convert the cart into one Google Sheets row per course seat
3. generate a unique OrderID for every row
4. write all rows to VBA_orders
5. wait for Google Sheets to confirm the write
6. only after a successful write, show the confirmation page

Prefer writing all rows for one checkout in one batch operation if the chosen Google Sheets method supports it.

Do not show a success confirmation before the Sheet write succeeds.

## CONFIRMATION

- the real saved OrderID or OrderIDs

If the checkout created several Google Sheets rows, show all relevant OrderIDs.

After a successful order, clear the cart so the same order is not accidentally submitted twice.

## ERROR HANDLING

If the Google Sheets write fails:

- do NOT show the success confirmation
- keep the user's cart and checkout information where practical
- show a clear bilingual error message
- allow the user to try again
- do not silently switch to another storage method

Prevent accidental duplicate submissions while the order is being saved.
