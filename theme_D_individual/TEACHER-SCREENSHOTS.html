AI FOR BUSINESS / INDIVIDUAL THEME D / TEACHER GUIDE

Add optional screenshot examples

Add only the examples you have time to prepare. Each image has its own link. No images are required for the reporting app to work.

Publish the images in GitHub, not in a student's upload field. The app checks for the matching file and shows See an example beside that screenshot field only when the image loads successfully.

1. Use this exact folder

The examples folder belongs next to the individual app's index.html. Using the pilot folder proposed in this chat:

materialbank/
  theme_d_individual_pilot/
    index.html
    styles.css
    app.js
    report.js
    data/
      pilot.json
    examples/
      README.md
      level-1-screen-1.png
      level-2-screen-1.png
      ...only the images you choose to provide...

Do not use the group-work folder theme_d. If you chose a different folder for the individual app, keep examples/ next to that app's index file. The app uses relative paths and does not depend on a particular repository folder name.

Use lowercase letters and hyphens, no spaces. Export real PNG images. The current pilot accepts these default names; no JSON editing is needed.

3. Publish any subset

Unzip the updated package and replace the app files in your individual pilot folder. Keep any example images already there. Open the examples folder in GitHub, choose Add file → Upload files, add the selected PNG files, and commit the change. Let your normal Pages publication finish, then refresh the app while online.

For example, uploading only level-2-screen-1.png gives only Level 2 / Screenshot 1 a See an example button. Screenshot 2 stays unchanged. Replacing the same filename changes the example after a fresh page load; removing the file removes the link after a fresh page load.

The link stays hidden when a file is missing, invalid, blocked, offline, or takes too long to load. This never blocks a student's work or PDF export. The app does not promise to distinguish a missing file from a network problem.

4. Keep the examples safe and useful

Use your own demonstration work with fictional information. Remove account menus and private identifiers. To hide answers, use solid opaque blocks and export a flattened image, not translucent highlighting. Check the final image before publishing. Keep headings, the field location and enough of the interface visible to show what the student should capture.

Teacher examples are guidance, not evidence. They are never copied into the student's screenshot slots, progress, backup or PDF. A student still has to provide screenshots of their own work. Do not put full answer keys in public images.

5. Quick local test

The standalone HTML preview uses the same relative paths. Put an examples folder next to the downloaded HTML, add one of the named PNG files and open the HTML. Without this folder, all optional links remain hidden and the reporting tool still works.

Do not refresh an offline reporting session just to look for new examples. Save a PDF or backup before closing a session.
